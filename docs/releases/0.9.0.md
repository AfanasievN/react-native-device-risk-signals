# v0.9.0 — Native SDK foundations and corrected signal semantics

This release advances the platform SDK extraction and corrects several observable values. Review
the migration notes before comparing historical events with newly collected events.

## Migration notes

- Fourteen iOS fields now emit JSON booleans instead of numeric `1`/`0`. Remove integer-specific
  parsing and accept `true`/`false`; the complete field list is in the changelog.
- Android `geolocation.locationAgeMs` supports ages above 2,147,483,647 ms without integer overflow.
  Storage and validation must accept 64-bit millisecond values.
- The Android active Frida handshake reassembles partial TCP replies. Positive observations can
  increase compared with previous releases; this remains unauthenticated raw evidence, not proof
  of a particular service. Connect and read budgets are 700 ms and 800 ms respectively.

## Improvements

- Extracted standalone Android collection and optional active-probe components, with native demos,
  transaction-session tests, artifact checks and Maven publication tooling.
- Established a standalone iOS Swift package and native demo; migrated selected providers and
  clarified native threading requirements.
- Added platform-neutral catalog and signal-type sources with automated drift validation.
- Expanded package-content, privacy, native-contract and documentation verification.
- Fixed Android release archive selection and shell-safe version validation.

## Install

```sh
npm install react-native-device-risk-signals@0.9.0
```

Refresh CocoaPods and rebuild the native application after upgrading. React Native 0.76+ with the
New Architecture remains required. The npm package continues to include the native sources used
by the binding; it does not require unpublished Maven artifacts.

Standalone Maven and Swift packages remain in development. This release publishes the React Native
npm binding only; it does not assert that other registry coordinates are available.
