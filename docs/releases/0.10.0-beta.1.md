# React Native Device Risk Signals 0.10.0-beta.1

**Experimental release for evaluation. Physical-iPhone QA has not been completed.**
Install explicitly with `npm install react-native-device-risk-signals@0.10.0-beta.1` or `@next`.
The stable `latest` channel remains on 0.9.1.

## What changed

- iOS hardware/fonts, cached location, media/app observations, security and transaction posture,
  and socket-free integrity now share the standalone iOS core implementation.
- The native iOS API exposes sixteen explicit methods through DeviceRiskSignals. Its independent
  Swift Package version is 0.2.0-beta.1; RN continues to compile shared sources through CocoaPods.
- UIKit-bound extracted providers require main-thread calls; the React Native adapter owns dispatch.
- A native example exercises all sixteen methods; SwiftPM includes a privacy manifest resource.

## Compatibility and privacy

No new JavaScript methods, event fields, probe defaults, permissions or network transport.
Android still consumes Maven core 0.1.0. Legacy RN iOS loopback/fork checks remain outside the
standalone package; the fork probe remains disabled by default. No risk score or verdict is added.
Standalone iOS omits active-port observations instead of manufacturing empty/false values.

## Validation and limitations

Local validation: 166 XCTest passes, one skip; simulator/device/Catalyst compilation; native and
React Native example builds; repository verification and npm package checks. Simulator results do
not validate real carrier data, jailbreak behavior, location availability, GPU performance or UI
budgets on physical devices. Existing platform omissions and privacy obligations remain.

Report integration issues with OS, device, Xcode and React Native versions; redact sensitive output.
Promotion out of beta requires representative physical-device QA. No stable-channel update occurs.
