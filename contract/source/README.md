# Probe catalog authoring source

This directory holds the framework-neutral authoring source for the probe catalog. It is plain JSON:
no TypeScript, no React Native types, and nothing that assumes which SDK or binding consumes it.

- `probe-catalog.source.json` is authored by hand.
- `../../src/probeCatalog.ts` is generated from it by `scripts/generate-probe-catalog.mjs` and must
  not be edited directly.
- `../probe-catalog.json` and `../raw-signal-event.schema.json` remain generated by
  `npm run docs:sync`, which still reads the TypeScript catalog. This slice moves authoring only; no
  generated artifact changes.

## Commands

```sh
node scripts/generate-probe-catalog.mjs --write   # regenerate src/probeCatalog.ts
node scripts/generate-probe-catalog.mjs --check    # fail if the committed file is stale
```

`--check` is also the default when no flag is passed. It prints the first differing lines in a
diff-style form and exits 1.

## Why one file, not one file per probe

The catalog is a single ordered list, and probe order is part of the contract: it drives the order of
rows on the published signal pages, of probes in `contract/probe-catalog.json`, and of properties in
the generated event schema. A single `probes` array makes that order explicit, stable, and reviewable
in one diff. Splitting into one file per probe would require a separate order manifest, which would be
a second source of truth for something the array already expresses, and would make a reordering or a
cross-probe review span nineteen files. At this size a single file also keeps a probe's neighbours
visible, which is how sensitivity, defaults, and permission wording stay consistent.

## Structure

| Key | Meaning |
| --- | --- |
| `sourceVersion` | Format version of this authoring file. |
| `enums` | Closed value sets (`probePlatform`, `probeSensitivity`). A generator derives the target-language type names from these keys. |
| `documentation.catalog` | Pre-wrapped lines of the doc comment that precedes the generated catalog. |
| `descriptor.fields` | Ordered shape of a probe descriptor: field name, neutral type, and `optional`. Field order here is the emitted key order. |
| `probes` | The ordered probe list. Every probe carries exactly the descriptor fields; `notes` is the only optional one. |

Neutral types are `string`, `boolean`, `enum` (with an `enum` key naming a set in `enums`), and
`array` (with an `items` type). A generator maps them to its own language: the TypeScript generator
emits `readonly ProbePlatform[]` for `{"type": "array", "items": {"type": "enum", "enum":
"probePlatform"}}`.

Prose fields (`purpose`, `notes`, `permissions` entries) are carried verbatim as single strings. The
generator, not the author, decides line wrapping in the emitted TypeScript.
